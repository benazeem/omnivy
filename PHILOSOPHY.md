# Omnivy Philosophy

## Save Knowledge, Not Page Noise

Omnivy is not trying to archive every pixel of a webpage. It tries to capture the part a user actually wants to keep: the article, answer, file, thread, conversation, or note.

Navigation menus, footers, sidebars, ads, recommendation blocks, and other page chrome should stay out of saved clips whenever possible.

## Browser First

The extension should work through browser capabilities before reaching for native apps or platform-specific background tools.

That keeps installation simpler and makes Omnivy easier to maintain across local Obsidian saves and cloud destinations.

## Site-Aware When It Matters

Generic extraction is useful, but many important websites need special handling. GitHub files, Stack Overflow answers, AI conversations, Notion pages, and forum threads all organize knowledge differently.

Omnivy favors focused extractors when they materially improve saved content.

## User-Owned Destinations

Users should choose where knowledge lives.

Omnivy supports local Obsidian workflows and cloud destinations because knowledge work does not happen in one tool only. The app should route content to the user's chosen destination without becoming a content host.

## Privacy By Default

Clipped content should be saved locally or sent only to the destination the user chooses.

Omnivy Web exists to handle sign-in, provider authorization, token refresh, integration settings, and request routing. It should not become a silent storage layer for clipped content.

## Useful Controls Over More Controls

The popup should expose controls users naturally need at save time: title, source, author, tags, custom properties, destination, vault/folder, and save status.

Settings should focus on behavior, appearance, vaults, and integrations. New features should reduce friction or improve extraction quality rather than adding noise.

## Long-Term Vision

Omnivy starts as a web clipper, but the larger goal is a flexible knowledge capture layer that works across browsers, local notes, cloud drives, workspaces, docs, forums, AI tools, and research sources.
